# 编码与文档规范

本文记录当前仓库的基础协作规范。后续随着项目推进可以继续补充。

## 文档语言

- README 和 `docs/` 下的文档统一使用中文。
- 技术名词可以保留英文，例如 Reactor、EventLoop、Channel、epoll、Buffer。
- 文档重点记录为什么这样做、遇到了什么问题、如何验证，而不是只描述代码表面行为。

## 代码注释

后续必要代码注释统一使用中文。

函数说明要求：

- 公开类、公开结构体和公开函数需要在头文件中写明用途。
- 构造函数应说明关键参数含义，例如端口、线程数、回调。
- 会阻塞、会启动线程、会关闭资源的函数必须说明调用效果。
- 异步回调、连接生命周期、跨线程访问和资源所有权需要说明约束。
- 内部辅助函数如果包含协议解析、状态机或平台差异，也需要简短说明。

建议添加注释的场景：

- 对象生命周期不直观。
- 跨线程调用有明确约束。
- fd 所有权容易误解。
- LT/ET 行为差异会影响实现。
- 关闭连接、移除 Channel、销毁 TcpConnection 等流程存在顺序要求。
- 某段代码是为了规避系统调用或并发边界问题。

不建议添加注释的场景：

- 函数名和变量名已经能清楚表达意图。
- 注释只是重复代码行为。
- 注释没有解释原因、约束或风险。

## 命名建议

- 命名空间使用 `csl`。
- 类型名使用 PascalCase，例如 `EventLoop`。
- 函数和变量使用 lowerCamelCase 或项目内后续统一风格。
- 文件名使用 snake_case，例如 `event_loop.h`。
